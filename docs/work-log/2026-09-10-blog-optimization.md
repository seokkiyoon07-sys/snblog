# 2026-09-10 배포 작업 정리 및 블로그 경량화

## 목적과 범위

Vercel 배포 지연과 블로그 구조를 검토한 뒤, 사용자가 승인한 네 가지 개선을 적용했다.

1. 불필요한 배포 작업 정리
2. 썸네일 경량화
3. 사이드바 서버 전환 및 미사용 Provider 제거
4. 알림·백업 경로를 현재 글 저장 구조에 맞게 수정

기존 Next.js 구조와 Vercel Git 연동을 유지했다. 프레임워크 교체, DB·CMS 도입, 새 캐시 계층 추가는 진행하지 않았다.

## 변경 내용

### 1. 배포 경로 정리

- `.github/workflows/deploy.yml`을 `Validate Blog` 검증 워크플로로 변경했다.
- 실패하던 별도 Vercel·Docker 배포 job을 제거했다.
- Node 버전은 `package.json`의 `22.x`를 참조하도록 통일했다.
- 설치, lint, 글 도구 테스트, 프로덕션 빌드, 홈 HTTP 응답 확인을 유지·구성했다.
- 같은 브랜치의 이전 검증을 취소하는 concurrency 설정을 추가했다.
- 출력만 수행하던 `simple-test.yml`, `test-notification.yml`을 제거했다.
- `scripts/deploy.sh`의 배포 전 무조건적인 `npm ci`·로컬 빌드를 제거했다. Docker 빌드의 `--no-cache`도 제거했다.
- 스크립트의 `all` 경로에서는 Git 푸시 뒤 Vercel CLI 배포를 다시 실행하지 않도록 했다.

운영 배포는 기존 **main 푸시 → Vercel Git 연동**을 사용한다. `vercel.json`은 변경하지 않았다. Actions 검증과 Vercel 배포는 독립적으로 실행되며, Actions 성공을 기다리는 배포 차단 기능을 새로 추가한 것은 아니다.

### 2. 썸네일 경량화

Git에 등록된 `public/images/thumbnail/`의 PNG/JPEG/WebP를 대상으로 작업했다. 작업 시작 전에 존재하던 미추적 이미지와 초안은 수정하지 않았다.

| 최종 결과                       |        수치 |
| ------------------------------- | ----------: |
| 실제 변경한 썸네일              |        94개 |
| 절감 용량                       | 약 120.8MiB |
| Git 추적 `public` 전체, 변경 전 | 약 351.7MiB |
| Git 추적 `public` 전체, 변경 후 | 약 230.9MiB |

- 기존 파일명·확장자·URL을 유지했다.
- 비율을 유지하면서 최대 1,280×1,280 경계 안으로 축소했다.
- 불투명 PNG는 팔레트 압축, 투명 PNG는 투명도를 유지하는 PNG 압축을 사용했다.
- JPEG·WebP는 품질 85로 압축했다. 더 작아지는 결과만 반영했다.
- 300KiB 미만 파일은 압축 대상에서 제외했다.
- 압축 파일 전체의 디코딩, 형식, 크기 및 투명도 보존을 확인했다.

초기 압축 결과는 95개·77.6% 절감이었으나 투명 PNG 보존 검증 후 일부를 재처리했다. 최종 결과는 위 표의 **94개·120.8MiB 절감**을 사용한다.

재사용 가능한 `scripts/optimize-thumbnails.cjs`와 `npm run optimize:thumbnails`를 추가하고, `sharp`를 개발 의존성에 명시했다. 압축은 게시 전 작업이며 Vercel 빌드 단계에는 넣지 않았다. 원본은 Git 이력에서 복구할 수 있다.

### 3. 사이드바 및 미사용 React Query 정리

- `src/components/Sidebar.tsx`의 `'use client'`를 제거했다. 최근 글·태그 계산은 서버에서 수행한다.
- 클릭 추적을 담당하는 기존 `TrackedPostLink`는 클라이언트 컴포넌트로 유지했다.
- 루트 레이아웃에서 `QueryProvider`를 제거했다.
- 미사용 `query-provider.tsx`, `use-posts.ts`, `query-client.ts`를 삭제했다.
- `@tanstack/react-query`, `@tanstack/react-query-devtools` 의존성을 제거하고 잠금 파일을 갱신했다.

관련 참조가 남지 않았음을 검색으로 확인했다. 기존 글 API는 유지했다. 빌드 요약의 First Load JS만으로 전체 전송량 감소를 정량화하지는 않았다.

### 4. 알림·백업 경로 수정

실제 글 정보는 `src/data/post-records.ts`, 본문은 `content/`에 있으므로 도구를 이 구조에 맞췄다.

**글 알림**

- 트리거 경로를 `src/data/post-records.ts`, `content/**`로 변경했다.
- `scripts/notify-posts.cjs`에서 푸시 이전·이후 메타데이터와 본문 변경을 비교한다.
- 새 글, 메타데이터 변경, 본문만 수정한 경우, 비공개에서 공개로 바뀐 경우를 감지한다.
- 여러 글 변경 시 각각 처리하며, 삭제된 글과 비공개 글은 제외한다.
- 문자열을 shell에서 조립하던 방식을 JSON 직렬화로 바꿨다.
- 기존 Jandi 목적지를 유지했다. 기본 실행은 dry run이며 `--send`가 있어야 전송한다.
- 알림은 푸시 기준이다. Vercel 배포 성공 알림으로 바꾼 것은 아니다.

**백업·복구**

- `scripts/post-backup.cjs`를 추가하고 기존 백업·복구 명령을 연결했다.
- `posts.ts`, `post-records.ts`, `content/` 전체를 날짜별 디렉토리에 백업한다.
- 복구 전 현재 상태를 먼저 백업한다.
- 백업 이후 추가된 본문 파일은 삭제하지 않는다.
- 예전 단일 `.ts` 백업은 새 복구 목록에서 제외한다.
- 이미지와 전용 React 컴포넌트는 이 백업에 포함하지 않으며 Git으로 관리한다.

운영 안내 문서 `POST_MANAGEMENT.md`, `SNBLOG_STRUCTURE.md`도 현재 구조에 맞게 갱신했다.
